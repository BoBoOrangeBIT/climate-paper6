# prompt_defects.md — GLACE Data Extraction Prompt v3.6-EN-ZAF, run ZAF_central_20261012

Situations the prompt does not cover or where following it literally would produce an evidently wrong record, recorded per §10. None were resolved by improvisation. `{RUN_ID}` = ZAF_central_20261012; rank reached 0; URLs as listed.

1. **No branch for a runner environment whose egress policy denies all HTTPS** (carried from NGA_split_20260827 #1, still open in v3.6). All 17 probed URLs — https://www.acdirect.co.za/, https://www.builders.co.za/, https://www.takealot.com/, nine T1b hosts, https://www.example.com/, https://www.google.com/ — were refused at the proxy CONNECT stage. §6 defines `C` and `C-geo` as field-level gap codes; the Step 7 table has no run-level stop value for a pre-frame block; `platform_blocked` is a coined value. Suggested addition: a formal Step 0 environment gate ("verify that PLATFORM_1, PLATFORM_2 and every Phase B source answer over the runner's network, with a control host, before §0.1; on failure emit `stop_reason = platform_blocked` and the reachability table") and an approved `stop_reason` value.
2. **§9.2 scope gate cannot express "unobservable".** The three outcomes (a)/(b)/(c) are decided on counts of 60 scanned items. With 0 observable items, outcome (c) `out_of_scope_with_evidence` would be false evidence of market absence, yet `scope_status` has only two permitted values. Suggested: add `undetermined_platform_blocked` (and leave `sample_status` empty) so a blocked run is never read as an out-of-scope finding.
3. **§0.1 validation result has no storage form within the run outputs.** The result goes only to `platform_evidence_result_v4.xlsx`, which is a companion file outside this repository. This run wrote the proposed row as `evidence/platform_evidence_row_ZAF_central_20261012.csv` with guessed column names; the template should fix the column layout or include the companion file with the run.
4. **`notes` is used by the body (Step 3 price basis, §9.3 test conditions, Step 5) but is not in the §5 field list; gap-code storage is likewise undefined** (carried from NGA #2). The records scaffold appends `notes` and a single `gap_codes` map column at the end of the §5 order. The template owner should decide between per-field companion columns and a map column.
5. **Mandated tool absent.** The prompt's execution build is "Claude Code × Claude in Chrome"; this managed runtime exposes no Claude-in-Chrome tools. The gate probe used curl and Playwright/Chromium as the nearest available real-browser substitute (gate only, no extraction). The prompt should state whether a managed runner with a scripted browser is an acceptable execution build, and if so under what rhythm and evidence rules (§3 item 1 is written for Claude in Chrome).
6. **robots.txt unverifiable is unhandled** (carried from NGA #3): §3 item 1 requires respecting robots.txt but says nothing when it cannot be retrieved. This run treated it as blocking.
7. **Token accounting** (carried from NGA #4): no runtime counter; estimates marked `estimated`. A standard estimation basis (characters ÷ 4) would make estimates comparable across cells.
8. **Checkpoint delegation** (carried from NGA #7): the prompt forbids self-approval but does not define whether or how the operator may pre-delegate Checkpoint 0/0b/1 approvals. In this run no delegation was given and none was assumed.
